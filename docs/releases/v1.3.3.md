## Highlights

### Memory Beads (preview)

b9s shows Memories and their Links when your `bd` is the [Memory Beads preview](https://blog.gascity.com/posts/extending-beads-memories-versions-and-the-wire-protocol/) build. With a released `bd`, b9s works as before, and it says in one line why the Memory views are not available.

In the terminal:

- `M` opens Memory wires. Issues are on the left, Memories on the right, and the selected record's Links are drawn between them. Each Link has its own heavy run with its kind word and UML head. `Enter`, a click or `d` opens the selected record in a detail panel beside the wires, like the tree's detail, and `d` hides it again: `1`-`9` follow a Link, `Backspace` goes back, and `Esc` returns to the wires. The strip below lists every Link of the selected record while the panel is closed. `Shift+Tab` hides or shows unrelated records, and `1` opens the Memory list with retained versions.
- The tree has a **MEMORY LINKS** column on terminals wider than 120 columns (`|` shows or hides it). The Issue detail lists Memory Links with direction, title and note. The column appears once the Memory graph has been read.
- `b9s memories` browses Memories, or prints them with `--print` and `--id`.

In `b9s web`:

- `M` opens the **Memory** tab, as in the terminal. It draws the relationship graph: Issues as orange circles, Memories as cyan cards.
- Select a record or a Link label to open it in the same detail panel the tree uses, with the same keys: `1`-`9` follow a Link, `Backspace` goes back, `n` and `p` step through records, `\` toggles full width, `c` copies the ID and `Esc` closes it. `d` hides the detail and shows it again, with the last selection. Mermaid diagrams render in Memory bodies.
- Zoom with the `−` and `+` buttons in the canvas corner, with `+`, `-` and `f` (fit) on the keyboard, with the mouse wheel or trackpad pinch, or with two fingers on a touch screen.
- Drag a record to move it, and its Links follow. The graph fills the view below the toolbar.
- **Labels** (or `l`) hides and shows the Link labels. **Line** `−` and `+` set the Link thickness from 1 to 6 px. The **Unselected opacity** slider fades records outside the selection. The **Link Type** filter and the **Record** picker narrow and find.

Both views draw each Link kind as the UML connector with the same meaning, and the legend names it:

| Link kind  | UML connector        | Line   | Head            |
|------------|----------------------|--------|-----------------|
| follows    | realization          | dashed | hollow triangle |
| depends on | dependency           | dashed | open arrow      |
| cites      | directed association | solid  | open arrow      |
| related    | association          | solid  | none            |

#### Fast startup, Memories on request

A graph workspace opens as fast as its Issue list: on our test workspace, the first screen shows in about 1 to 2 s instead of 6 to 7 s. b9s reads the Memory graph only when you open a Memory view or an Issue detail, in the terminal or in `b9s web`. While it reads, the view and the detail's MEMORY LINKS section show a progress bar, for example `Reading Memory Links ▰▰▱ 3/8`. After a change to the workspace, b9s reads the graph again and keeps the old one on screen until the new one arrives.

#### Availability

b9s decides availability from the workspace metadata and from `bd`'s help output, which it caches per binary. Run `b9s --reprobe` after you replace `bd` in place. Set `B9S_MEMORY=off`, or `memory: off` in the config file, to hide the Memory views. A graph workspace still shows its Issues.

To try it, follow "Use the preview bd in your own repository" in the User Guide. The decisions are ADRs 0036 to 0051.

### Web board

The web board matches the terminal board:

- Each issue is one line, with `blocked`, `lane`, `blocks`, `P0` and `P1` tags at the right.
- A child sits indented below its parent in the same cell.
- The epic cell shows the first sentence of the description, progress, the in-progress, waiting and ready counts, labels, owner, due date and last change.

### Demo

The demo project is a web shop of 52 issues: five epics hold features, the features hold tasks and bugs, and two milestones ship the epics. The demo shows the release version it runs.

## Fixes

- In the tree, the detail opens on the selected child when the search keeps the child only for its matching parent.
- In the web detail, consecutive Markdown lines join into one paragraph, and bold text that spans a line break renders as bold.

## Upgrade notes

- Nothing changes for a released `bd`. The Memory views need the Memory Beads preview `bd` and a graph workspace created with it. Do not point the preview at an existing Beads project.
