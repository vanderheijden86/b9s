T8 · commit detail

Commit, issue and agent in one place

Recommendation

Terminal first for agents, web for the 2D views

  1. T7 commits as a quick win. Read-only git log with the Refs column. It needs no new collector and replaces the lgl pane in tmux.
  2. T1 + T2 + T3 next. The agents resource with logs and context. It is the k9s model, it works over ssh, and every later view reads the same collectors.
  3. Then W1 and W4 in b9s web. The fleet board and the context matrix. They need the second dimension and give the most insight per screen.
  4. T4 and W6 as the cross-project landing. Mostly counts that b9s can already read from the shared Dolt server.
  5. Later: T8 commit detail (after T1 gives session links), T5 xray, T6 pulse, W5 timeline (needs history), W3 constellation (after W4 proves the data).
Where the data comes from
Claude Code sessionsTranscripts in ~/.claude/projects/<path>/*.jsonl. Tail for logs. Loaded CLAUDE.md files and compactions are events in the file.
Codex sessionsRollouts in ~/.codex/sessions/YYYY/MM/DD/*.jsonl. Same tailing collector, different parser.
Omnigent lanesPods in the lane namespace via the Kubernetes API. Logs by kubectl logs or the session file in the pod. Lane labels give task and role.
tmux panestmux list-panes -a maps a laptop session to a pane, so a can attach to it.
BeadsAlready read. A task link comes from the lane label, the branch name, or the session id in a claim comment.
